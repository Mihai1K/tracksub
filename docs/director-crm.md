При полном конфиге `CRM_SESSION_BRIDGE_TOKEN` (случайный отдельный секрет,
минимум 32 символа) и `CRM_DIRECTOR_EMAIL` директор видит верхний пункт CRM.
В Контенте появляются ссылки Заказы / Рассылки / Контент; все существующие
страницы, рабочие пространства и действия Контента сохраняются.
У остальных пользователей остаётся прежнее меню.

Директор определяется одновременно по `users.is_admin = 1` и точному
совпадению нормализованной почты с конфигурацией. Одного статуса admin мало.
Существующая cookie `sid` и таблица sessions остаются единственным источником
входа. Пароли, идентификаторы и записи контента не переносятся.

Соседняя CRM обращается по loopback к `/internal/crm/session`:
GET проверяет действующую сессию, DELETE отзывает её при выходе.
Обязательны loopback peer, отдельный Bearer и `X-Crm-Session` с sid.
Ответы no-store, содержат только id/email либо ok, без cookie/паролей.
Публичный Caddy должен отдельно блокировать `/internal/crm/*` до proxy.
В заголовки и логи браузера секрет моста не передаётся.

`/login?next=/crm` сохраняет только фиксированное назначение `/crm`,
внешние адреса отвергаются. Уже вошедший посторонний admin получает 403,
без цикла переадресаций. Вход остальных пользователей по-прежнему ведёт в `/app`.

## Выпуск и откат

Выпуск только после отдельного подтверждения владельца и восстановления SSH.
Перед ним сравнить REVISION/изменённые файлы с установленной версией на HostKey,
сохранить предыдущий код и конфигурацию, проверить роль директора коротким
SELECT без password_hash. Не выгружать .env, cookie и секреты в отчёт.
У этого локального репозитория Git remote отсутствует: отдельного PR/CI нет.

Сначала установить код обоих веб-сервисов с выключенным мостом, закрыть
публичный internal path, затем настроить одинаковые секрет/email и явное
сопоставление существующему DIRECTOR в BloggerMarket CRM. Включить SSO в CRM,
проверить обычный кабинет, Контент, CRM, общий выход и запрет чужого доступа.
Воркер BloggerMarket не перезапускать, разрешения рассылок не менять.

Откат: выключить `CRM_TRACKSUB_SSO` в CRM, убрать конфигурацию моста TrackSub
и вернуть предыдущие версии веб-сервисов. Возвращается отдельный вход CRM.
Миграций и копирования БД нет, восстановление старой БД не требуется и
затёрло бы новые рабочие данные. Отозванные общим выходом сессии потребуют
обычного повторного входа; их не восстанавливать.
