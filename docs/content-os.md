# Content OS: тренды → сценарии

Раздел «Контент» в кабинете TrackSub. Собирает публичные посты каналов и пабликов,
считает, какие из них залетели, и превращает выбранный тренд в сценарий ролика.
Атрибуцию не трогает: свои таблицы `content_*`, своя вкладка, свой фоновый сборщик.

## Поток

Источник → сбор → залётность → лента → сценарий → «к съёмке» → «снято» → «опубликовано».

У каждого пространства (workspace) свои источники, лента, сценарии и профиль автора.
Личный блог и Blogger Market - два пространства, создаются в «Профиль автора → Отдельное пространство».

## Источники

| Площадка | Как | Что нужно |
|---|---|---|
| Telegram | публичная веб-версия `t.me/s/<канал>`: текст, просмотры, реакции | ничего; с сервера в РФ Telegram закрыт - нужен `CONTENT_TG_WEB_BASE` на прокси |
| VK | `wall.get`: просмотры, лайки, репосты, комментарии, подписчики | `VK_SERVICE_TOKEN` - сервисный ключ приложения (vk.com/apps?act=manage) |
| YouTube | тренды по региону, поиск за 14 дней, канал по @handle | `YOUTUBE_API_KEY` |
| vidIQ, ChatPlace Virale | ручной импорт: JSON, CSV/TSV или ссылки построчно | ничего; API подключим, когда будут ключи |

Строки для добавления: `@channel`, `https://t.me/channel`, `vk.com/public`, `youtube.com/@handle`,
`yt: запрос`, `yt: тренды RU`. Стартовые наборы (28 проверенных каналов) - `src/content/presets.js`.

Репосты и реклама в ленту не попадают. Поиск YouTube по русскому запросу оставляет только кириллицу.

## Залётность

`outlier` = просмотры поста / медиана просмотров постов этого канала старше суток (нужно ≥ 8 постов).
Для трендов, поиска и импорта - просмотры / подписчики автора (только если подписчиков ≥ 1 000
и просмотров ≥ 10 000), иначе оценка поставщика, иначе «нет оценки». Цифры не придумываются.

Порядок в ленте: `log2(1 + outlier) × свежесть × (1 + бонус вовлечённости до 40%)`.
Свежесть 1 до 3 дней, 0,5 к 14 дням. Посты младше суток помечены «ранний».

## Сценарии

- Без ключа: каркас по профилю автора с пометками `[вставь ...]` вместо выдуманных фактов,
  плюс готовый промпт для Claude/ChatGPT и форма, куда вставить ответ.
- С `ANTHROPIC_API_KEY`: Claude (`CONTENT_AI_MODEL`, по умолчанию `claude-opus-5-5`), ответ по JSON-схеме.
  При ошибке API - каркас и честное сообщение о причине.
- Везде только обычный дефис. Скачивание сценария в `.md`.

## Настройки окружения

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `CONTENT_COLLECTOR` | `on` | фоновый сбор (проверка очереди раз в 10 минут) |
| `CONTENT_FETCH_HOURS` | `12` | как часто обновлять один источник |
| `CONTENT_BATCH` | `20` | источников за один проход |
| `CONTENT_TG_WEB_BASE` | `https://t.me` | базовый адрес веб-версии Telegram (HTTP-прокси) |
| `CONTENT_TG_PROXY` | пусто | `socks5://host:port` - чтение t.me через SOCKS-туннель HOSTKEY |
| `VK_SERVICE_TOKEN`, `YOUTUBE_API_KEY`, `ANTHROPIC_API_KEY` | пусто | ключи площадок, необязательные |

## Перед выпуском

1. Доступ к Telegram с Selectel: туннель bm-tg-tunnel слушает 127.0.0.1:11081 на хосте, контейнер его не видит. Нужен
   туннель на адресе docker-сети (или `network_mode: host` для сборщика) и `CONTENT_TG_PROXY=socks5://<адрес>:11081`.
2. Выпустить `VK_SERVICE_TOKEN`, перенести `YOUTUBE_API_KEY` в `.env` TrackSub.
3. Новые таблицы создаются сами при старте (`CREATE TABLE IF NOT EXISTS`), существующие данные не меняются.
   Перед выкаткой - обычный бэкап `tools/backup.js`.
