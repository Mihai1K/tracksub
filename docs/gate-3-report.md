# Gate 3–5 — отчёт: продукт собран

Дата: 05.09.2026. Статус: **работающий MVP**. Сквозной путь проходит целиком на mock-интеграциях,
живые токены не подключались.

---

## 1. Что проверено

- Сквозной путь: регистрация → проект → канал → бот → ссылка → клик → подписка вебхуком →
  атрибуция → дашборд → расход → CPS → конверсия. Автотест, не ручная проверка.
- Идемпотентность, CSRF, закрытость админки, демо-режим, шифрование токенов — тестами.
- Миграция схемы на базе, созданной предыдущей версией: старые данные на месте, колонки добавились.
- Восстановление из резервной копии: копия открывается, таблицы и данные целы.
- Производительность редиректа: 500 запросов, p50 = 0,24 мс, p95 = 0,57 мс.
- Docker: сборка образа, запуск контейнера, healthcheck, права на файловую систему.

## 2. Что подтверждено

| Область | Состояние |
|---|---|
| Аккаунты | scrypt, сессии в БД, сброс пароля гасит все сессии, лимит попыток входа |
| Изоляция проектов | все выборки идут через `workspace_id`, чужой проект недоступен |
| Telegram | адаптер разбирает `chat_member` / `chat_join_request` / `/start`; вступление несёт ссылку → атрибуция точная |
| MAX | адаптер разбирает `user_added` / `user_removed` / `bot_started`; источника в событии нет → честная вероятностная схема |
| Пул ссылок | ссылки готовятся заранее, редирект их только забирает; пул пуст → уходим по ссылке канала без задержки |
| Атрибуция | три типа, уверенность, спорность, кандидаты, пересчёт без потери истории |
| Аналитика | CR, CPS, D1/D7/D30 со зрелостью когорты, стоимость живого подписчика, строка «источник неизвестен» |
| Конверсии | очередь, ретраи с паузами, статусы, `skipped` при отсутствии `yclid` |
| Безопасность | CSRF, rate limit, секреты вебхуков сравниваются постоянным временем, токены клиентов зашифрованы AES-256-GCM |
| Эксплуатация | Docker, `/health`, структурные логи, бэкап через `VACUUM INTO`, проверенное восстановление |

## 3. Что не подтверждено

1. **Ни одного реального события платформ.** Всё на mock-клиентах. Требуются токены.
2. **Ни одной реальной отправки в Яндекс.** Формат загрузки офлайн-конверсий реализован по
   документации, но живой ответ Метрики не видели.
3. **E1 из Gate 1 по-прежнему открыт**: приходит ли `user_added` в MAX при самостоятельной подписке.
   Если нет — в MAX останется только схема через бота.
4. **PostgreSQL.** DDL написан, драйвер не переписан, на живой базе не проверялся.
5. ~~Docker-образ~~ — **подтверждён**: образ собирается (232 МБ), контейнер стартует, `/health`
   отвечает, docker healthcheck переходит в `healthy`, регистрация работает. Процесс идёт от
   непривилегированного пользователя `app`, код принадлежит root и приложению на запись недоступен,
   пишется только `/app/data`.

## 4. Известные ограничения

- Почта не отправляется: ссылка сброса пароля пишется в лог сервера.
- Приём платежей ручной: тарифы и лимиты работают, YooKassa не подключена.
- Удаление данных по сроку тарифа объявлено, но не реализовано — сделать до продажи тарифов.
- Rate limit живёт в памяти процесса: при нескольких инстансах нужен общий счётчик.
- Агентский воркспейс, роли, white-label, VK, Meta, Google — не в MVP.
- Атрибуция одноканальная (last eligible click), мультитач и кросс-девайс не делаются намеренно.
