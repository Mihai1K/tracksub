# Content OS: дорожная карта

Цель - находить темы, которые сработают именно для наших двух аудиторий, раньше других,
превращать их в сценарии и учиться на собственных публикациях.

Оценка темы - четыре независимых сигнала, итоговый рейтинг - прозрачная формула:

| Сигнал | Вопрос | Где считается |
|---|---|---|
| Velocity | рано ли мы увидели | спринт 1 (готов) |
| Outlier | необычно ли для канала | есть с этапа 1 |
| Topic Heat | подтверждают ли другие источники | спринт 2 |
| Relevance | наше ли это (отдельно для каждого пространства) | спринт 3 |

## Спринт 1 - история замеров и скорость (готов)

- `content_snapshots (item_id, observed_at, views, likes, comments, shares)`, ключ `(item_id, observed_at)`.
  Снимок пишется на каждом сборе, повтор в течение 20 минут не пишется, старше 30 дней - по одному в сутки.
- Повторные замеры по площадкам:

  | Площадка | Как перезамеряем | Ограничение |
  |---|---|---|
  | Telegram | страница t.me/s каждые 2 ч | видны ~20 последних постов: у очень частых каналов (Mash) пост уходит из окна за ~10 ч |
  | VK | wall.get каждые 2 ч, 50 последних постов | хватает с запасом |
  | YouTube | videos.list по ID свежих роликов (до 3 суток) каждые 3 ч | 1 единица квоты на 50 роликов |
  | Импорт vidIQ/Virale | только при повторной вставке | автоматически не перезамеряется |

- Расчёт (`src/content/velocity.js`): скорость = прирост просмотров / часы между снимками (окна < 30 мин отбрасываются);
  при одном снимке - средняя с публикации с пометкой; прирост за ~6 ч; пик скорости;
  **норма канала** = медиана скорости других свежих (< 48 ч) постов того же источника, нужно ≥ 5;
  тренд: растёт (> +20%), ровно, замедляется (< -20%), стоп (< 0,5% прироста). Падение счётчика - окно пропускается.
- Старые посты получают первый снимок из прошлого сбора - скорость видна с первого сбора после выкатки.
- В карточке: скорость, «×N к норме канала», тренд, прирост, мини-график. Сортировка «По скорости роста».
- Формула залётности **не менялась**: скорость показывается рядом, в рейтинг войдёт после проверки на данных.

## Спринт 2 - склейка инфоповодов и Topic Heat (готов)

```
content_topics (id, workspace_id, title, first_seen_at, last_seen_at, status, heat, sources_count, views_sum, velocity_sum)
content_topic_items (topic_id, item_id, similarity, is_primary, added_by: auto|llm|manual, PRIMARY KEY (topic_id, item_id))
```

Склейка в два шага:
1. Быстрый - нормализация (без эмодзи, ссылок, хэштегов), извлечение «опорных» слов: имена собственные, бренды,
   числа, даты. Кандидаты - посты за 3 дня. Сходство - по опорным словам с весом редкости (TF-IDF по корпусу),
   а не по общим словам: «новая модель ChatGPT» и «ChatGPT подорожал» делят бренд, но не действие.
2. Спорные пары (средний порог) - проверка LLM строго `same_event` / `different_event` с причиной, только если задан ключ.
   Без ключа спорные пары не склеиваются: ложная склейка хуже пропущенной.

Независимость источников: репост и пересказ одного первоисточника - одно упоминание; источник считается один раз
на тему. `heat = независимые источники × log2(1 + сумма просмотров) × свежесть × (1 + скорость к норме)`.
Ручные действия: «это одна тема», «разделить».

## Спринт 3 - релевантность для двух пространств (готов)

Сделано (`src/content/relevance.js`): слова интересов из «Темы» и «Для кого» + словарь ниш (ИИ, бизнес, реклама,
блогеры, маркетинг, запуск...), общие слова профиля отброшены; стоп-темы в профиле (по умолчанию политика, война,
происшествия), короткие - только целым словом; оценка 0..1, «наше» от 55%, «может быть» от 20%, у каждой оценки
подсказка «совпали: ...». 👍/👎 в карточке: ручная оценка главнее расчёта, опорные слова поста получают ±0,5
(предел ±2). В ленте по умолчанию скрыто «не наше» (кроме импорта), фильтр «Только наше / Все посты»;
темы сортируются по температуре × (0,4 + 0,6 × релевантность). Журнал `content_events`: избранное, архив,
сценарий, оценки. Профиль показывает, по каким словам ищет и что выучил.

Было в плане:

Профиль автора уже есть у каждого пространства (кто, для кого, темы, тон). Добавляется:

```
content_relevance (item_id | topic_id, workspace_id, score 0..1, label: personal|blogger_market|both|off_topic, by: rule|llm|user)
content_events (workspace_id, item_id, topic_id, kind: open|favorite|unfavorite|script|archive|publish, at)
```

Старт - правила: ключевые слова тем профиля и стоп-темы (политика, происшествия - для Blogger Market off_topic).
Затем - явная разметка пользователем одним кликом и поведение с разным весом
(публикация > сценарий > избранное > открытие; архив - отрицательный сигнал). Проценты - ориентир, не вероятность успеха.

## Спринт 4 - тема → сценарий → публикация → результат (готов)

Сделано (`src/content/publications.js`): блок «Публикации» в сценарии (ссылка, дата, какой из трёх хуков
или свой), автозамер YouTube (videos.list), Telegram (страница поста ?embed=1) и постов VK (wall.getById):
первые 3 суток раз в 6 ч, потом раз в сутки, до 8 дней; Instagram/TikTok/клипы VK - ручной ввод
(просмотры, лайки, переходы, заявки). Вкладка «Результаты»: вехи 24 ч / 72 ч / 7 дн (ближайший замер ±40%,
иначе пусто), разбивки по источнику темы, хуку, формату, площадке, «тема из нескольких источников vs одиночный
пост» - медиана к 72 ч, меньше 3 роликов = «мало данных». Сценарий по теме хранит topic_id.

Было в плане:

`content_scripts` уже связан с постом (`item_id`) и хранит ссылку на ролик. Добавляется:

```
content_scripts + topic_id, hook_type
content_publications (id, script_id, platform, url, published_at)
content_publication_metrics (publication_id, observed_at, views, likes, comments, shares, saves, clicks, leads)
```

Метрики своих роликов - вручную, затем через PostMyPost аналитику. Отвечаем на вопросы: какие источники дают темы,
которые доходят до публикации; какие хуки дают просмотры; какие темы приносят заявки.

## Спринт 5 - Telegram: утренняя сводка и алерты (готов)

Сделано (`src/content/notify.js`): привязка чата из «Профиля автора» одноразовым кодом (`/start cos_<код>`
в боте TrackSub), отдельно для каждого пространства; утренняя сводка в выбранный час МСК (по умолчанию 9:00):
до 5 тем за сутки по температуре × релевантности + посты с разгоном ×2+ к норме канала, пустую не шлём;
алерты 8:00-23:00: пост ×5+ к норме по замерам (не «не наше») или тема от 3+ источников за 6 ч с релевантностью
≥ 0,5; не больше 5 в день, без повторов (журнал `content_notifications`); заблокировал бота - подписка снимается.
Кнопки - ссылки с подписью HMAC (действие, объект, пространство, срок 7 дней): «☆ В избранное» и «Сценарий»
выполняются после входа на сайт. Вебхук бота не меняли: callback-кнопки потребовали бы `callback_query`
в allowed_updates - можно позже.

Было в плане:

Через уже работающего бота TrackSub (@tracksub_analytics_bot), отдельно для каждого пространства.

- Сводка 09:00 МСК: топ-5 **тем** (не постов) по heat × relevance, прирост за ночь, источники.
- Алерт - только адаптивные пороги: скорость ≥ 5× нормы канала, или тема в 3+ независимых источниках за 6 ч,
  при релевантности не ниже порога. Не чаще одного алерта на тему за 6 ч, не больше 5 в день.
- Кнопки: `cos:f:<topic>` избранное, `cos:s:<topic>` сценарий, ссылка «Открыть». Обработчик проверяет, что
  нажал участник этого пространства, повторное нажатие идемпотентно, `answerCallbackQuery` всегда.
- Журнал доставки `content_notifications (workspace_id, kind, ref, sent_at, status)` - для дедупликации и разбора.
